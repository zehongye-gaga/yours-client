# Yours Client 产品需求

记录日期：2026-10-24。

Yours Client 让用户通过聊天使用 Agent，并把需要长期使用的能力组织成持续运行、可交互、可升级的应用工作台。用户的应用配置和业务状态需要跨会话、跨客户端重启保留。

## 产品目标

完整产品应支持以下流程：用户提出需求，Agent 发现已有能力，创建或安装应用，宿主激活应用并显示界面，用户通过界面与 Agent 持续协作，应用状态持续保存。

首版先建立这个流程的运行基础：使用内置或本地导入的可信插件，实现真实 Agent 调用、独立 Node 运行环境、动态界面和版本升级。自然语言生成任意新应用属于后续阶段。

## 已确认的产品决策

| 决策 | 当前选择 |
| --- | --- |
| 客户端形态 | Electron 桌面端 |
| 首发平台 | macOS Apple Silicon，保留跨平台架构 |
| 首版交付 | 可运行基础版，包含真实模型与工具调用 |
| Agent 来源 | 客户端直连模型并管理工具调用与会话 |
| 模型协议 | OpenAI 兼容 Chat Completions，配置 Base URL、API Key 和模型名称 |
| 插件来源 | 可信内置插件和已构建的本地插件目录 |
| 微内核 | 直接引入 Cordis core 源码作为可修改的本地分支，沿用原生 API |
| 首个业务场景 | GitHub 项目状态工作台 |
| 当前开发顺序 | 先复用并验证 Cordis，再实现产品服务、运行适配和桌面界面 |

## 首版产品能力

| 能力 | 用户可感知的行为 |
| --- | --- |
| 模型设置与聊天 | 配置模型服务，发送消息，接收流式结果，查看工具执行状态并取消任务 |
| 会话管理 | 保存和恢复聊天记录、工具执行结果及关联工作台 |
| 插件管理 | 安装、启动、停止、卸载和升级可信插件，查看版本、运行状态和错误 |
| Node 业务运行环境 | 插件在受管理的独立进程中持续运行，具有独立数据目录 |
| 动态工作台 | 插件激活后显示界面，数据变化后更新视图，停止后正确撤销入口 |
| Agent 与应用协作 | Agent 调用插件工具，工作台中的操作可以触发 Agent，并展示执行结果 |
| 状态持久化 | 客户端重启后恢复插件启用配置、工作台配置及业务数据 |

首版使用单个本地用户及其 Workspace、Session 作用域。云端多租户、组织策略和跨设备同步放在后续阶段。

## GitHub 工作台验收场景

1. 用户配置模型服务，启用 GitHub 插件并指定一个项目。
2. 用户在聊天中查询项目状态，Agent 实际调用插件提供的工具并返回结果。
3. 工作台展示项目状态、Issue 和 Pull Request 等数据；后续数据变化可以更新界面。
4. 用户从面板发起 Agent 操作，执行进度和结果能回到当前应用或会话。
5. 用户停止插件后，工具和界面入口被撤销，其他会话仍可使用。
6. 用户导入同一插件的新版本，完成就绪检查和注册切换；准备失败时继续使用旧版本。
7. 退出并重新启动客户端后，插件配置和业务状态仍可恢复。

原始需求中的“添加 PR 审查按钮”可作为升级场景：首版通过导入已构建的新版本实现；后续由 Agent 生成该改动。是否向 GitHub 发布评论或修改远端数据，需要在该具体功能中单独定义授权行为。

GitHub 鉴权方式、刷新频率、限流策略和具体指标在业务插件设计阶段确定，不阻塞当前微内核设计。

## 架构约束

### 微内核与运行能力

Cordis 管理进程内 Context、服务依赖、插件 Fiber、受管资源和事件。产品 Workspace、实例身份和注册事务在其上补充。Agent Loop、模型适配器、工具注册、MCP、存储、权限策略、进程管理和 UI Slots 通过服务与适配器接入。

这些机制分别支撑插件组合、可靠启停、按 Workspace 配置能力，以及业务注册项的一致发布由另建的注册服务实现。模型执行、页面渲染、进程隔离和数据保存由对应服务完成，具体分工见[微内核职责与需求映射](architecture/microkernel-responsibilities.md)。

| 能力类别 | 作用 | 运行位置 |
| --- | --- | --- |
| Agent 能力 | 模型、工具、Skill、Memory 和执行流程 | 可信宿主服务或受控远程代理 |
| 业务 Runtime | 长期任务、数据处理、业务状态及工具处理器 | 受管理的 Node 子进程 |
| View | 消息卡片、面板、应用页面和交互 | 声明式渲染、可信 React 扩展或隔离 iframe |

这三类是可组合的能力。同一个插件包可以同时包含业务 Runtime、工具和 View。包、运行实例与进程之间不固定为一对一关系。

### 服务与业务注册项

Agent 依赖稳定的工具注册服务；GitHub 搜索等具体工具是该服务内的注册项。业务插件升级需要同时切换工具与 UI 注册，避免为了更新一个工具而重启整个 Agent。

### UI 与数据更新

UI 方向保留 Schema Renderer、React Slots 和隔离 iframe 三种形式。可信宿主扩展可使用 React；完整业务应用通过隔离界面和受控 Bridge 接入。渲染器不直接获得本地 Node 或系统权限。

插件更新通过宿主事件通道传递到 UI。视图保留修订号和序号，断线或发现序列缺口时重新获取快照。桌面端的实际传输由宿主适配，微内核不绑定 WebSocket 或 Electron IPC。

### 存储与权限

- 代码版本与业务数据目录分开管理，升级不覆盖用户数据。
- 会话事件与业务数据分开存储；本地持久化以 SQLite 和文件为设计方向。
- API Key 等凭证由宿主管理，不直接下发给界面或任意插件。
- 服务可见性与调用授权分别校验；敏感操作通过 Broker。
- 普通 Node 子进程不提供操作系统级文件隔离；首版仅运行可信代码。
- 将来开放任意生成代码之前，需要增加与目标平台相适应的安全隔离。

### 个性化编排与应用生成

长期产品通过三类配置组织体验：Capability Profile 决定启用的能力，Experience Profile 决定界面和布局，Agent Profile 决定 Agent 的执行方式与策略。

配置来源依次包括基础配置、组织策略、角色或 Workspace、用户偏好、会话配置和任务级 UI。组织禁用与权限上限是持续生效的约束，后续层不能覆盖它们。任务级配置先在当前会话生效，用户选择保存后才能成为长期工作台配置。

Agent Creator 的流程包括验证真实数据源、生成代码、构建与静态校验、隔离预览、读取错误并修复、发布和后续升级。发布运行新的代码需要相应授权。插件调用 Agent 时需受并发、调用预算、超时与取消策略约束。

## 后续阶段

| 阶段 | 交付内容 |
| --- | --- |
| 当前阶段 | 引入并维护 Cordis 本地分支，运行原生测试与样例，定义产品服务边界 |
| 首版运行基础 | Electron 宿主、Node 进程、模型调用、插件管理、动态 UI、持久化和 GitHub 工作台 |
| Agent Creator | 数据源验证、代码生成、构建、隔离预览、发布及迭代修改 |
| 个性化编排 | Capability、Experience、Agent Profile 的组合，权限约束和会话级配置 |
| 分发与同步 | 远程安装、插件市场、发布治理、组织能力和跨设备同步 |

首版不包含完整插件市场、云端每用户 Runtime、公开运行不可信代码，以及 Agent 自动生成任意插件的完整流程。
